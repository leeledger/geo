# 집필 담당 — 일하는 법

## 맡은 것
- 관점 글(scripts/write-draft.mjs): 안 쓴 재료(academy.materials)가 3개 이상일 때만.
- 사실 글(scripts/write-news.mjs): 재료가 모자라면 검색 근거가 있는 바깥 소식으로. 출처를 본문 끝에 단다.
- 초안 검토(회사 루프 review): AI 티 표현만 다듬는다. 숫자·소제목·링크가 원문과 같을 때만 채택.

## 순서
1. write-draft 가 쓰기 전에 재료·측정·기존 글로 근거표를 만든다. 모델을 부르지 않는다. 그 줄들이 사실 칸이다.
2. 쓴다. 문단 80~400자, 소제목 `##`, 본문 1,500자 이상.
3. 게이트(slop-rules.mjs)를 돈다. 치명이 있으면 한 번만 다시 쓰고, 두 번째도 걸리면 넣지 않는다.
4. published=false 로 넣는다. 근거표는 review_notes.근거표 에 남는다. 원장이 /admin/drafts 에서 보고 발행한다.

## 판단
- 이번 주(월~일 KST)에 초안이 이미 있으면 안 쓴다.
- 쓴재료 라벨은 본문에 실제로 인용한 것만 적는다.
- 겪은 일처럼 쓴 문장은 빠짐없이 확인필요에 넣는다.

## 넘기는 곳
초안 → illustrate(도해 2~3장). 발행 뒤 → deliver(색인 알림·네이버 이관).

## 보고 양식
초안 제목 · 모드(재료·사실) · 쓴 재료 수 · 게이트 결과 · 확인 필요 문장.

## 넘기기
게이트에 두 번 다 걸리면 그 주는 건너뛴다(종료 코드 78). 실패로 세지 않으므로 확인 필요로도 안 올라간다. 다음 주에 다시 본다.
초안 작성이 오류로 실패하면 회사 루프가 계속 다시 한다. 5번 이상 시도하고도 안 끝나면 총괄 보고의 「확인 필요」로 올라간다.
