# 주간 정리

레퍼런스는 가만 두면 늙는다. 주 1회 숫자를 새로 재고 영업 자료를 갱신한다.

## 1. 플레이스 순위

```
cd tools && node naver-place-check.mjs
```

브라우저가 필요해서 자동으로 못 돈다. 주 1회는 사람이 있을 때 돌린다.
지역 검색은 웹문서보다 플레이스가 위에 뜨므로, **이쪽이 실제 유입에 더 가깝다.**

## 2. 케이스 리포트 갱신

```
cd academy && node scripts/case-report.mjs --out ../web/public/case/academy.html
```

공개본은 학원 이름·지역·사이트 주소·경쟁 학원·글 주소를 가리고 날짜를 「N일차」로 바꾼다.
원본이 필요하면 `--private` 로 뽑되 `web/public` 에는 두지 않는다 (스크립트가 막는다).

`serp` 워크플로가 매일 돌리지만, 사람이 한 번은 열어서 읽어 본다.
**굳은 문장이 없는지** 본다 — 사실이 바뀌었는데 문장이 그대로면 레퍼런스로 못 쓴다.
(예: "아직 구글 크롤러는 오지 않았습니다" 라고 적힌 채 Googlebot 이 113회 다녀간 적이 있다)

## 3. 한 주 변화 정리

DB에서 한 주 치를 뽑아 견준다.

```
크롤러   커버리지가 오른 곳 · 새로 온 크롤러
노출     새로 잡힌 검색어와 그 날짜
발행     몇 편 · 주 1편을 지켰나
색인     구글 접수 누계
```

**숫자를 나열하지 말고 무엇이 움직였는지 말한다.**
안 움직였으면 안 움직였다고 적는다. 그게 다음 주 판단의 근거가 된다.

## 4. 밀린 것 점검

- 초안이 쌓여 있으면 왜 안 나갔는지
- 주제 은행이 5개 아래로 내려갔으면 채운다
- 구글 색인이 전부 접수됐으면 이 항목은 닫는다

## 문의가 들어오고 있는가

이제 상담 기록이 DB 에 쌓인다. 사람에게 묻지 말고 직접 읽는다.

```sql
select * from academy.inquiry_summary limit 3;
```

보는 것
- 이번 달 문의 몇 건인가
- 그중 검색·AI 로 온 사람이 몇인가  ← 노출이 문의로 이어지는지의 유일한 증거
- 등록으로 이어진 게 몇인가

**기록이 0건이면 그걸 앞에 놓고 보고한다.** 노출을 아무리 잘 재도
문의 기록이 없으면 이 사업이 되는지 증명할 수 없다.
원장님께 상담 때 한 줄씩 남기시라고 말한다 — 화면은 만들어져 있다.
  /admin/inquiry?key=...

## 단위경제로 환산

원생 한 명 = 월 18.5만원. 재원 12개월이면 222만원.
대행비 월 79만원이면 연 948만원 — **순증 4~5명이 본전**이다.

그래서 매출 전체를 볼 필요가 없다. 그 4~5명만 세면 손익이 나온다.
검색·AI 로 온 문의가 몇 건이고 그중 몇이 등록했는지, 그 두 숫자면 된다.
