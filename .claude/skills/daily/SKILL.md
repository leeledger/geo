# 아침 루틴

혼자 하는 회사다. 매일 같은 순서로 돌려서 빠뜨리는 걸 없앤다.
**보고만 하고 끝내지 말 것.** 할 수 있는 건 그 자리에서 처리한다.

## 1. 브리핑

```
cd academy && node scripts/briefing.mjs
```

여기서 나온 「오늘 할 일」이 오늘의 목록이다. 하나씩 처리한다.

## 2. 노출 측정

```
cd academy && node scripts/check-index.mjs
```

Bing·네이버를 재고 DB에 날짜와 함께 남긴다.
**처음 노출된 날이 영업 자료다.** 새로 잡힌 질의가 있으면 반드시 보고한다.

## 3. 구글 색인 요청

```
cd tools && node submit-gsc.mjs --all
```

- 하루 한도가 약 10건이다. 「하루 한도 초과」가 뜨면 정상이고, 거기서 멈춘다
- 접수한 주소는 `gsc-done.json` 에 쌓이므로 다음 날 이어서 간다
- 로그인이 안 돼 있으면 `open-session.mjs` 를 열고 **사람에게 로그인을 요청**한다

## 4. 새 글이 있으면 색인 알림

어제 이후 발행한 글이 있으면:

```
cd academy && node scripts/indexnow.mjs "https://robotncoding.com/blog/<슬러그>"
```

사이트맵은 15분마다 다시 만들어진다. 갓 올린 글은 사이트맵에 아직 없으니
**주소를 직접 준다.** 사이트맵만 믿으면 새 글을 빼먹는다.

## 5. 문의가 들어왔는가

브리핑에 문의 기록이 함께 나온다. 어제 이후 새 문의가 있으면
어떤 경로로 왔는지 보고한다. 특히 **AI 나 검색으로 온 건**이 있으면
반드시 짚는다 — 그게 이 사업이 되는지를 말해 주는 유일한 숫자다.

기록이 계속 0건이면 매일 반복해서 말하지 말고, 주 1회만 짚는다.
같은 말을 매일 하면 소음이 된다.

## 6. 보고

숫자를 그냥 나열하지 말고 **어제와 견줘서** 무엇이 움직였는지 말한다.

- 크롤러 커버리지가 오른 곳 / 새로 온 크롤러
- 새로 잡힌 검색어
- 밀린 것과 그 이유

## 판단

- **주 1편이 목표.** 마지막 발행이 7일 넘었으면 그날은 `post` 스킬로 글을 쓴다
- 크롤러가 24시간 동안 하나도 안 왔으면 사이트가 죽은 것일 수 있다. 먼저 확인한다
- 밀린 게 없으면 그렇게 말하고 끝낸다. 일을 만들어내지 않는다
