# 문서딱 세션에 넘기는 제안 — 성장 리포트 기계용 데이터 (사이티드, 2026-10-05)

사이티드는 reports/growth/YYYY-WW.md 를 매일 읽어 현황판·파일럿 보고에 싣는다(사이티드 Step 36). 문서딱 코드는 우리가 안 고친다. 아래는 그쪽 절차(설계 → 개발 → 리뷰)로 판단해 달라는 부탁이다. 안 해도 우리 쪽은 돈다.

## 1. growth-data JSON 에 표 원자료 (필요)

지금 리포트 끝 growth-data JSON 에는 합계(range7·range28·last7·last28)와 cf 만 있다. 쿼리·페이지 표는 마크다운에만 있다.
그래서 우리는 「| 쿼리 | 클릭 | 노출 | CTR | 평균 순위 |」 표를 글자로 읽는다. 표 모양이 바뀌면 우리 쪽 표가 빈다(합계는 산다).
JSON 에 queries7·queries28(상위 25면 충분)·pages28 를 반올림 전 값으로 넣어 주면 표를 안 읽는다.

## 2. 하루 단위 배열 (있으면 좋음)

주 단위로도 레퍼런스 기록은 된다. 날짜별 그래프가 필요해지면: 서치콘솔 dimensions ['date'] 28일, Cloudflare 는 fetchTraffic 이 이미 받는 일별 묶음을 cf.daily 로.

## 3. A-6 에 순위 8~30 구간 (있으면 좋음)

지금 A-6 은 「노출 50 이상·CTR 2% 미만」과 「안내 없음, 노출 10 이상」 두 가지다. 2026-10-05 dry_run 에서 둘 다 0개였다(7일 노출 36, 평균 순위 18.2).
노출이 작은 지금은 「평균 순위 8~30, 노출 10 이상, 이미 안내가 있음 → 보강 후보」 표가 하나 더 있으면 할 일이 보인다. 기준값은 그쪽이 정한다.
